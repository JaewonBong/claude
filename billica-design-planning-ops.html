빌리카 디자인·기획서 운영 시스템

Figma 「[MO] BILLY Design」 페이지(약 2,800개 노드, 모바일 375px)의 프레임 구조를 분석해 만든 초안입니다. 파일 구조, 네이밍, 기획서 양식, 업무 흐름, 품질 기준을 한 번에 정리합니다.

시각 스크린샷과 색상·타이포 토큰은 가져오지 못했습니다(Figma 이미지 호스트 접근 차단). 토큰 항목은 추후 보강이 필요합니다.

관찰된 패턴

  • 모든 기능에 오류·없음·마감·완료 상태 프레임이 따로 있음
  • 공통 컴포넌트: Header, Bottom_BTN, Button, Status Bar, Dim 팝업
  • 변경 이력은 [YYMMDD] 사유 텍스트 노트로 기록
  • 사용자 유형 3종(일반회원, 비회원, SK구성원)에 따라 전체메뉴가 분기

개선 필요

  • 프레임명 오타: 차랑목록, 얘약공유하기, 침 이용 동의
  • 같은 이름의 중복 프레임이 다수
  • 모든 도메인이 한 페이지에 있어 캔버스가 5만 px를 넘음
  • 상태 프레임과 기획 문서가 연결되어 있지 않음

디자인 시스템

  • Foundation: 색상, 타이포, 간격, 라운드, 그림자를 Figma Variables로 정의
  • Components: Header, Button, Bottom_BTN, Input, Tooltip, Dim 팝업, 카드, 탭, 칩
  • 하드코딩 값 금지. 신규 컴포넌트는 리뷰 후 등록
  • 토큰은 개발 쪽 Code Connect 매핑 대상으로 관리

3. 기획서 표준 양식

화면 한 장당 기획서 한 장. 아래 10개 항목을 고정 순서로 작성합니다.

#항목작성 내용
1메타화면 ID, 화면명, 도메인, 담당(기획·디자인·개발), 상태, 버전
2목적과 진입 경로이 화면이 해결하는 문제, 이전 화면과 진입 조건
3사용자 유형별 차이일반회원 / 비회원 / SK구성원
4구성 요소와 데이터요소별 노출 조건과 데이터 출처
5상태 정의정상, 입력중, 오류, 빈 상태, 마감, 완료
6유효성과 오류 문구입력 규칙, 오류 메시지 원문
7예외 처리결제 실패, 재고 없음, 일정 불가, 시간 초과
8연동 시스템결제, 본인인증, 알림톡, 제휴사
9분석 이벤트이벤트명, 발생 시점, 파라미터
10변경 이력날짜, 변경 요약, 담당, 이슈 키

화면 ID 체계: {도메인코드}-{번호}-{상태번호}. 예) RSV-012-03은 예약 도메인의 12번 화면(결제), 3번 상태(실패)입니다.
